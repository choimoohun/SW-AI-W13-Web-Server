# C 웹 서버 과제 명세

요구사항은 이 프로젝트 대화에 제공된 과제 원문을 따른다. 실행 명령은 [README](../README.md), 코드 구조와 후속 설계안은 [DESIGN](design.md)을 참조한다. 저장소의 단계 번호에는 개발 준비가 포함되어 있다.

## 공식 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 환경 | C, 표준 C 라이브러리, POSIX API를 사용한다. Windows에서는 WSL2 Ubuntu, Linux 컨테이너 또는 클라우드에서 개발한다. 플랫폼 전용 API를 선택하면 지원 환경을 기록한다. 외부 HTTP 파서·서버 프레임워크·완성된 이벤트 루프 라이브러리는 사용하지 않는다. |
| TCP | `socket()` → `bind()` → `listen()` → `accept()` 순서로 연결을 받고, 연결별 FD에서 데이터를 송수신하고 닫는다. |
| HTTP | GET·POST 요청의 메서드·URI·버전, `Host`·`Content-Length`·`Connection` 등 헤더, POST 본문을 처리한다. 상태 줄, `Content-Type`·`Content-Length`·`Connection` 등 응답 헤더, 본문을 보낸다. |
| 콘텐츠 | 지정한 문서 루트에서 정적 파일을 제공하고 HTML·CSS·JS·PNG·JPG 등의 MIME 타입과 `403`·`404`·`500` 오류를 처리한다. 요청에 따라 CGI 실행 또는 백엔드 전달 등으로 동적 응답을 제공한다. |
| 동시성 | `fork()`, `pthread`, I/O 멀티플렉싱 중 하나 이상을 사용한다. `pthread`를 선택하면 스레드 풀이 권장된다. I/O 멀티플렉싱을 선택하면 이벤트 루프로 여러 연결을 관리한다. |
| 프록시 | Forward Proxy 또는 Reverse Proxy를 최소 한 가지 구현한다. Forward Proxy는 요청 URL의 목적지에 연결해 중계하며 캐싱은 선택이다. Reverse Proxy는 경로 또는 호스트에 따라 백엔드로 라우팅하며 Round-Robin은 권장이다. 정적 파일을 직접 제공할지 전달할지는 구현 결정이다. |
| 빌드·실행 | Makefile 또는 CMakeLists.txt를 제공한다. 포트, 문서 루트, Reverse Proxy를 선택한 경우 라우팅 규칙을 CLI 인자 또는 설정 파일로 받는다. |
| 종료·정리 | `SIGPIPE`를 무시하고 쓰기 실패를 처리한다. `SIGINT`·`SIGTERM`에서 안전하게 종료하고 정상·오류 경로의 FD와 할당 자원을 회수한다. |

과제 원문은 RFC 7230~7235를 학습 범위로 제시한다. 실제로 지원할 메시지 형식과 연결 정책은 구현 결정에 남긴다. 팀 README와 확인한 필수 기능은 일치한다. README는 C17·CMake 및 Docker/WSL2 환경으로 빌드하는 방법을 구체화한다.

## 개인 구현 결정

| 항목 | 상태 | 근거 또는 결정 시점 |
| --- | --- | --- |
| C17·CMake | 확정 | 팀 기본 틀의 [CMakeLists.txt](../CMakeLists.txt)에 설정되어 있다. |
| 로컬 빌드 환경 | 확인 | Docker Desktop의 Linux 컨테이너에서 CMake 빌드와 통합 테스트를 확인했다. |
| 현재 TCP 연결 방식 | 확정 | 기본 실습 모드에서 연결 한 건을 처리한다. 프록시·예약 모드는 연결을 하나씩 처리하고 다음 연결을 받는다. [순차 연결](concurrency/connections.md) |
| 첫 HTTP 구현 범위 | 확정 | HTTP/1.1 GET·POST와 `/`로 시작하는 요청 대상을 처리한다. 요청 줄과 헤더는 합쳐서 4 KiB, 본문은 8 KiB까지 받는다. `Content-Length`로 본문 길이를 읽고 응답 후 연결을 닫는다. |
| 첫 정적 파일 범위 | 확정 | 기본 문서 루트는 `public`이고 `/`는 `index.html`에 연결한다. 파일은 4 KiB 버퍼로 나누어 보내고, 문서 루트 밖의 경로와 심볼릭 링크는 거절한다. 예매 예제는 HTML 파일 하나에 스타일과 좌석 선택 스크립트를 둔다. |
| keep-alive·chunked의 최종 지원 범위 | 미결정 | 첫 구현은 `Connection: close`로 응답하고 `Transfer-Encoding` 요청에는 오류를 반환한다. 프록시를 붙이기 전에 최종 범위를 확인한다. |
| 프록시, 동적 처리, 라우팅, 타임아웃 | 구현, 타임아웃 검증 대기 | [예약 API](dynamic/booking.md)는 C 백엔드의 메모리로 상태를 관리한다. [프록시](dynamic/proxy.md)는 CLI로 경로 접두사와 백엔드 IPv4 주소·포트를 받고 백엔드 중계에 3초 기한을 적용한다. [진행 상태](progress.md)에 확인한 응답을 기록한다. |
| 동시성 모델과 자원 소유권 | 검토 중 | [동시 요청 설계안](concurrency/workers.md)에서 고정 워커 풀과 제한된 작업 큐를 제안한다. 구현 전 과부하·종료 정책을 확정한다. |
| 부하 조건과 합격 기준 | 미결정 | 1.6에서 측정 환경과 기준값을 기록하고 최종 검증 조건을 정한다. |

## 작업 단위와 완료 기준

| 단계 | 학습·구현 단위 | 완료 기준 |
| --- | --- | --- |
| 1.1 | 개발 준비 | 선택한 POSIX 환경에서 기존 CMake 구성과 빌드를 실제로 실행해 컴파일러와 `socket()` 사용 가능 여부를 확인한다. |
| 1.2 | TCP 연결과 송수신 · CS:APP 11.4 | TCP 클라이언트로 바이트가 왕복하고 연결 FD를 정리한다. 연결이 중단된 뒤에도 다음 클라이언트를 처리한다. |
| 1.3 | HTTP 요청과 응답 · CS:APP 11.5 | GET·POST를 처리한다. 분할 수신과 헤더·본문의 동시 수신에서 경계를 식별하고, 불완전하거나 길이 제한을 넘는 입력을 정한 정책대로 처리한다. |
| 1.4 | 정적 파일 서빙 · CS:APP 11.6 참고 | 브라우저에서 정적 콘텐츠와 MIME 타입을 확인한다. 대표 오류 응답과 문서 루트 밖 접근 방지를 검증한다. |
| 1.5 | 동적 요청과 프록시 | 프록시 왕복과 입력에 따라 달라지는 동적 응답을 확인한다. 대상 서버 연결 실패와 타임아웃 처리를 검증한다. |
| 1.6 | 동시 요청과 종료 처리 | 한 연결이 대기하는 동안 다른 요청을 처리한다. 연결 중단과 종료 신호의 자원 정리를 확인하고 첫 부하 측정값을 기록한다. |
| 1.7 | 전체 통합과 최종 검증 | 문서대로 빌드·실행 및 설정 변경을 재현한다. 통합·예외·부하·자원 검사 결과를 기록한다. |

1.3의 공통 HTTP 요청·응답 구조를 기반으로 1.4와 1.5를 각각 구현하고 검증한다. 1.6에서 전체 서버의 동시 동작과 종료를 확인한다.

## 검증 계획

- **단위와 기능** … TCP 바이트 왕복은 TCP 클라이언트로 확인한다. HTTP 응답이 생기면 `curl`과 브라우저로 확인한다. HTTP 파서, MIME 매핑, 라우팅 또는 중계 로직은 단위 테스트로 검증한다.
- **예외와 통합** … 비정상 메서드·버전, 불완전한 헤더, 긴 URI·큰 본문, 클라이언트 연결 중단, 대상 서버 장애·지연을 확인한다. 요청 하나가 끝난 뒤 다른 요청도 처리되는지 확인한다.
- **1.6 부하 기준값** … 프로젝트 테스트 환경에서 같은 정상 요청의 동시 접속 수를 단계적으로 올리고 처리량·응답 지연·실패율을 기록한다.
- **1.7 최종 검증** … 같은 조건을 다시 측정한 뒤 정상·예외 요청을 섞어 검증한다. 예상된 오류 응답과 비정상 실패를 따로 기록하고 FD 회수와 sanitizer 또는 Valgrind의 메모리 검사 결과를 확인한다.

실행한 명령과 결과는 [진행 상태](progress.md)에 기록한다.
