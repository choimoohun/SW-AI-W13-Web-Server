# 웹 서버 테스트 결과

- **기능 검증** — 자동 회귀 테스트 3개 통과, 같은 좌석에 들어온 동시 예약 8건 중 매회 1건만 성공
- **추가 발견** — 동시 요청 16개의 혼합 부하에서 일부 POST의 본문 전송 중 `BrokenPipeError` 재현
- **다음 확인** — 과부하 시 POST 연결 종료 시점, 부담이 줄어든 뒤 응답 복구 시간, 브라우저의 예약 충돌 안내

## 기능과 예외 처리

| 테스트 | 테스트 조건 | 관찰 결과 |
| --- | --- | --- |
| 자동 회귀 | 나눠 보낸 POST, HTML·이미지 요청, 예약·프록시·동시 처리 실행 | 테스트 3개 모두 통과 |
| 예약 상태 변경 | 빈 좌석 조회 → 예약 → 재조회 → 같은 좌석 재예약 | `200 → 201 → 200 → 409`, 재조회에서 예약 상태 반영 |
| 같은 좌석 동시 예약 | 매회 새 백엔드의 빈 좌석 1A에 예약 8건 동시 전송, 두 차례에 각각 12회 반복 | 모든 회차에서 `201` 1건·`409` 7건, 재조회에서 예약 상태 확인 |
| 백엔드 중단과 복구 | 프록시는 켜둔 채 예약 백엔드 중단 후 재시작, 두 차례에 각각 12회 반복 | 중단 중 예약 API `502`·정적 페이지 `200`, 재시작 후 API `200` 복구 |
| 백엔드 응답 지연 | 예약 API가 백엔드를 기다리는 동안 별도 연결에서 정적 페이지 요청 | API는 약 3초 뒤 `504`, 정적 페이지는 약 4ms에 `200` 응답 |
| 작업 큐 포화 | 워커 4개와 대기 큐 8칸을 채운 뒤 추가 요청, 포화 해소 후 정적 페이지 재요청 | 포화 시 `503`, 해소 후 `200` 응답 |
| 미완성 요청과 잘못된 입력 | 헤더 일부만 전송하거나 헤더 누락·잘못된 본문·크기 초과 요청 전송 | 미완성 헤더는 약 5초 뒤 `408`, 나머지는 각 조건에 맞는 오류 응답 |
| 종료 신호 | 유휴 상태에서 `SIGINT`, 처리 중인 연결과 대기 큐가 남은 상태에서 `SIGTERM` 전송 | 유휴 상태는 약 30ms, 작업이 남은 상태는 약 4.7초에 종료 |
| 자원 정리 | 부하 전후 유휴 FD 비교와 Valgrind 검사 | 프록시·백엔드 모두 유휴 FD `6 → 6`, 메모리 오류 0건, 종료 시 남은 힙 0바이트 확인 |

## 1. 단일 경로 부하 — 같은 요청만 반복

- **조건** — 정적 페이지(`/`)와 좌석 조회(`/api/seats`)를 각각 측정, 경로마다 동시 요청 4개와 16개로 약 4초씩 반복
- **동시 요청 수** — 한 클라이언트가 응답을 받은 뒤 다음 요청을 보내는 방식, 4·16은 동시에 요청을 보내는 클라이언트 수
- **표 읽는 법** — 전체는 약 4초간의 요청 건수, 성공은 `200` 응답 건수, `503`은 과부하 거절 건수
- **지연 읽는 법** — 성공 p95가 33.36ms라면 성공 요청의 약 95%가 33.36ms 안에 응답 본문까지 수신

| 측정 | 테스트 경로 | 동시 요청 | 전체 | 성공 `200` | 과부하 `503` | 초당 성공 | 성공 p95 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 기준 | 정적 페이지 | 4 | 5,914 | 5,914 | 0 | 1,478.2 | 3.68ms |
| 재측정 | 정적 페이지 | 4 | 2,898 | 2,898 | 0 | 723.7 | 9.11ms |
| 기준 | 정적 페이지 | 16 | 7,205 | 6,087 | 1,118 | 1,517.7 | 14.80ms |
| 재측정 | 정적 페이지 | 16 | 4,751 | 2,703 | 2,048 | 672.9 | 33.36ms |
| 기준 | 좌석 조회 | 4 | 10,139 | 10,139 | 0 | 2,533.8 | 2.59ms |
| 재측정 | 좌석 조회 | 4 | 8,000 | 8,000 | 0 | 1,999.4 | 3.78ms |
| 기준 | 좌석 조회 | 16 | 8,596 | 8,511 | 85 | 2,125.4 | 12.39ms |
| 재측정 | 좌석 조회 | 16 | 5,980 | 5,510 | 470 | 1,369.8 | 22.13ms |

- **관찰** — 동시 요청 4개에서는 전부 `200`, 16개에서는 두 경로 모두 `503` 발생, 전체 구간에서 전송 오류 0건
- **비교 범위** — 경로·동시 요청 수·측정 시간은 동일, 당시 시스템 부하와 요청 생성 방식의 일치 여부는 미확인

## 2. 혼합 부하 — 정상 요청과 오류 요청을 함께 전송

- **조건** — 클라이언트마다 아래 다섯 요청을 번갈아 전송, 동시 요청 4개는 1회·16개는 2회, 구간당 약 4초
- **집계 기준** — 요청별로 기대한 상태 코드의 수신 건수, `503` 수신 건수, HTTP 응답 확인 전 전송 실패 건수

| 요청 유형 | 기대 응답 |
| --- | --- |
| 정적 페이지 열기 | `200` · HTML 수신 |
| 좌석 상태 조회 | `200` · 좌석 목록 수신 |
| 존재하지 않는 API 호출 | `404` · 경로 없음 |
| 필드가 빠진 예약 요청 | `400` · 잘못된 입력 |
| 이미 예약된 좌석에 재예약 | `409` · 좌석 상태 충돌 |

| 동시 요청 | 전체 | 기대 응답 | 과부하 `503` | POST 전송 실패 |
| --- | ---: | ---: | ---: | ---: |
| 4 | 3,662 | 3,662 | 0 | 0 |
| 16 · 1차 | 5,656 | 3,891 | 1,157 | 608 |
| 16 · 2차 | 5,437 | 2,765 | 1,779 | 893 |

- **확인한 결과** — 동시 요청 16개의 두 실행 모두 POST 본문 전송 중 `BrokenPipeError` 발생
- **가능한 원인** — 큐 포화로 서버가 연결을 닫는 시점과 클라이언트가 POST 본문을 보내는 시점의 겹침, 연결별 실제 순서는 미확인
