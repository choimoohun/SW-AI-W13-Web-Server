# 실제 구현·동작 원리

이 문서는 HTTP 스펙이나 POSIX 규격이 아니라, **이 서버에서 실제로 일어나는 일**을 적는다.
API 규격과 선택 근거는 `docs/notes/iomux.md`, 선택 이유는 `docs/decisions/`에 있다.

## 1. TCP 소켓은 IP+포트만으로 식별되지 않는다

표준 문서는 소켓을 `<protocol, IP address, port number>`로 정의한다. 그런데 실제 동작은 다르다.

- 같은 서버(IP:포트)로 여러 연결이 들어오면, 그 연결들을 구분하려면 **보낸 쪽 주소**까지 봐야 한다.
- 실제로는 `<src IP, src port, dst IP, dst port>` 4튜플로 식별한다.
- 그래서 서버가 같은 `IP:포트`를 공유하는 여러 `conn fd`를 구분할 수 있다.

우리 서버에서: `listen fd`는 모든 연결이 같은 `IP:포트`를 쓰지만, `accept()`가 돌려주는 각 `conn fd`는 클라이언트 4튜플이 달라서 커널이 구분한다. `src/tcpserver.c`, `src/worker.c`.

## 2. 커널 수신은 2단계

- 1단계(Wait for Data): 데이터가 도착할 때까지 기다린다.
- 2단계(Copy Data): 커널 수신 버퍼 → 유저 공간 버퍼로 복사한다.

블로킹 `recv()`는 1단계에서 스레드를 점유한다. 논블로킹은 1단계를 건너뛰고 2단계만 시도하고, 데이터가 없으면 `EAGAIN`을 돌려준다. 우리 서버는 후자만 쓴다. `src/connection.c`의 `on_readable()`.

## 3. `listen fd`와 `conn fd`는 다르다

- `listen fd` — `socket()` + `bind()` + `listen()`. 연결 요청을 받는 문.
- `conn fd` — `accept()`가 만드는 실제 통신 소켓. `accept()`한 워커가 끝까지 소유한다.

`listen fd`는 워커 4개가 공유하고, `conn fd`는 워커가 각자 소유한다. 그래서 fd 핸드오프 큐가 없다.

## 4. 레벨 트리거(LT) / 엣지 트리거(ET)

- LT: "읽을 데이터가 있다" 상태가 유지되는 동안 계속 통지. 덜 읽어도 다음 `wait`에서 다시 알려준다.
- ET: 데이터가 0에서 양수로 변하는 시점에만 통지. 그 반복에서 다 읽지 않으면 다음 통지를 기다려야 한다.

우리는 `EPOLLET`를 쓰지 않는다. 기본 LT다. `src/iomux.c`.

## 5. accept 분산

- `listen fd`를 4개 워커가 공유하고, 각자 `iomux_add(listen fd, READ)`로 등록한다.
- 커널이 깨워준 워커는 `accept()`를 **한 번만** 한다. `EAGAIN`이면 그냥 리턴.
- 왜 한 번만 하나: `EAGAIN`까지 반복하면 첫 워커가 연결을 다 가져가서 한 스레드에서 직렬 처리되고, 좌석 경쟁(동시성 데모)이 사라진다.

`src/worker.c`의 `accept_ready()`.

## 6. `dup()`로 소유권 이전하기

프록시 요청은 워커가 직접 백엔드와 통신하지 않는다.

- `proxy_submit()`이 클라이언트 fd를 `dup()`해 복사본을 큐에 넣는다.
- 워커는 원본 fd를 닫고 바로 이벤트 루프로 돌아간다.
- 프록시 전용 스레드가 복사본을 가져와 백엔드와 통신하고, 다 끝나면 닫는다.

`dup()`이 왜 필요한가: 같은 파일 테이블 항목을 두 주체가 가리켜야 하므로, 복사본을 만들어 소유권을 분리한다. 양쪽이 같은 fd를 닫으면 double-close다. `src/proxy.c`.

## 7. 유휴 연결 정리

- `iomux_wait()`에 200ms 타임아웃을 줘서, 준비된 이벤트가 없어도 주기적으로 루프를 돈다.
- `cleanup_idle()`이 마지막 활동 후 5초가 넘은 연결을 닫는다.
- keep-alive 최대 100회에 도달한 연결도 여기서 정리한다.

"요청 정리"가 아니라 "연결 정리"다. 요청은 버퍼에서 `req.consumed`만큼 제거하고, 연결은 유휴 시간으로 닫는다. `src/worker.c`, `src/connection.c`.
