# STUDY.md — 처음 보는 사람도 바로 이해하는 웹서버·네트워크 용어집

## 1. 꼭 알아야 할 핵심 용어 11가지

| 용어 | 쉬운 비유 | 우리 C 코드에서는 무슨 뜻인가요? |
|---|---|---|
| **Socket (소켓) & FD (파일 디스크립터)** | 전화기 & 창구 번호표 | 컴퓨터는 인터넷 연결도 파일처럼 **정수 번호(`int fd`)**로 관리합니다. `3번`, `4번` 같은 번호표에 `read()`하면 글자를 받고, `write()`하면 글자를 보냅니다. |
| **Blocking vs Non-blocking** | 줄 서서 기다리기 vs 진동벨 받기 | **Blocking**은 상대방이 말할 때까지 코드가 그 줄에서 얼어붙어 기다립니다. **Non-blocking**은 아직 말이 없으면 *"아직 안 왔네(`EAGAIN`)"* 하고 바로 빠져나와서 다른 손님을 봅니다. |
| **Event Loop (`poll`/`epoll`/`kqueue`)** | 홀 매니저의 진동벨 알림판 | 손님 100명을 한 명씩 물어보지 않고, **"지금 실제로 글자를 보낸 손님 번호표"**만 OS가 콕 집어 알려주는 대기 루프입니다. (`poll`은 맥북·리눅스 공통 표준입니다.) |
| **Concurrent (동시성) vs Parallel (병렬성)** | 1명이 빠르게 번갈아 하기 vs 여러 명이 진짜 동시에 하기 | 일꾼 1명이 진동벨로 100명을 번갈아 처리하는 게 **동시성**, 일꾼(`fork` 프로세스)을 CPU 코어 개수만큼 여러 명 띄워 진짜 동시에 일하게 하는 게 **병렬성**입니다. 둘을 합친 게 **Nginx 방식(Hybrid)**입니다. |
| **SO_REUSEADDR** | 방 빼자마자 다음 사람 바로 받기 | 서버를 껐다 바로 켜면 운영체제가 안전을 위해 방금 쓰던 포트 번호를 30초쯤 묶어둡니다. 이 옵션을 켜야 기다리지 않고 바로 재시작할 수 있습니다. |
| **Keep-Alive & EOF** | 전화 안 끊고 계속 말하기 vs 상대가 전화 끊음 | **EOF**(`read() == 0`)는 상대방이 전화를 끊었다는 신호입니다. 옛날 HTTP/1.0은 1번 말하고 바로 끊었지만, HTTP/1.1(`Keep-Alive`)은 전화를 안 끊고 다음 요청을 기다립니다. 그래서 **`Content-Length`에 적힌 글자 수만큼만 딱 읽고 멈춰야** 합니다. |
| **SIGPIPE & EPIPE** | 끊긴 전화기에 대고 소리치면 터지는 폭탄 | 손님이 데이터를 받다가 브라우저 창을 확 닫아버렸는데 서버가 계속 `write()`를 하면, OS가 *"잘못된 파이프 쓰기!"*라며 서버를 강제 종료시켜 버립니다. 그래서 시작할 때 `signal(SIGPIPE, SIG_IGN)`으로 무시해야 합니다. |
| **Graceful Shutdown** | 영업 종료 후 뒷정리 다 하고 퇴근하기 | `Ctrl+C`를 눌렀을 때 바로 전원을 뽑지 않고, 열려 있던 소켓을 다 닫고 빌려 쓴 메모리(`malloc`)를 모두 반납(`free`)한 뒤 깨끗하게 끝내는 것입니다. |
| **Forward Proxy vs Reverse Proxy** | 내 대신 장 봐주는 비서 vs 회사 안내데스크 | **Forward Proxy**: 클라이언트(나) 편에서 외부 인터넷에 대신 접속해 줍니다. (사내 보안, 접속 통제, 캐싱 목적)<br>**Reverse Proxy**: 서버 편에서 손님 요청을 대신 받아 내부의 여러 백엔드 서버로 나눠줍니다. (부하 분산, 서버 숨기기) |
| **L4 vs L7** | 택배 송장(주소)만 보기 vs 박스 뜯어 내용물 보기 | **L4**는 IP 주소와 포트 번호만 보고 길을 나눕니다(단순·빠름). **L7**은 HTTP 안의 URL(`/api/`인지 `/images/`인지)과 헤더까지 읽고 길을 나눕니다. 우리 리버스 프록시가 L7입니다. |
| **CGI** | 외부 계산기 프로그램 잠깐 불러서 쓰기 | 웹서버가 직접 HTML 파일을 주는 게 아니라, `fork()` + `pipe()` + `execve()`로 외부 프로그램을 실행해서 그 프로그램이 화면에 출력한 결과를 손님에게 돌려주는 옛날 표준 방식입니다. |

## 2. 자주 헷갈리는 핵심 개념 Q&A

### Q1. 왜 코치님이 `멀티 프로세스 + 이벤트 루프(Hybrid)`가 좋다고 했을까?
* **요청마다 프로세스 만들기(`fork`)**: 손님이 1,000명 오면 프로그램 1,000개를 복사해야 해서 메모리가 금방 터집니다.
* **스레드(`pthread`)만 많이 쓰기**: 스레드끼리 같은 메모리를 공유하다 보니, 서로 동시에 값을 고치다 꼬이는 걸 막으려 잠금장치(Lock)를 걸어야 해서 느려지고 버그가 잘 납니다.
* **이벤트 루프(`poll`/`epoll`)만 1개 쓰기**: 아주 가볍고 빠르지만, 일꾼이 1명뿐이라 컴퓨터의 CPU 코어를 1개밖에 못 씁니다.
* **합친 방식(Hybrid = Nginx 구조)**: CPU 개수만큼만 딱 워커 프로세스(일꾼)를 띄우고, 각 일꾼이 각자의 이벤트 루프로 수천 명을 상대합니다. 서로 메모리를 안 섞어서 안전하고, CPU도 끝까지 다 쓸 수 있습니다.

### Q2. 프록시에서 "캐시가 두 군데에 있다"는 게 무슨 말인가요?
* **클라이언트 쪽 캐시 (브라우저 / 포워드 프록시)**: 내가 자주 보는 웹사이트 로고나 JS 파일을 내 컴퓨터나 회사 프록시에 저장해 두어, 멀리 있는 외국 서버까지 매번 가지 않게 합니다.
* **서버 쪽 캐시 (리버스 프록시 / CDN)**: 우리 백엔드 서버 앞단에서 인기 있는 상품 목록이나 이미지를 미리 저장해 두었다가, 손님이 올 때마다 DB까지 안 가고 앞단에서 바로 쏴주어 서버를 보호합니다.

### Q3. IP 주소 1개에 도메인 이름을 여러 개 쓸 수 있게 해주는 `Host` 헤더란?
* 한 컴퓨터(IP `203.0.113.10`) 안에서 `쇼핑몰.com`과 `블로그.com` 두 개를 같이 운영할 수 있습니다.
* 네트워크 선을 타고 들어올 땐 IP만 적혀 있어서 어느 사이트를 원하는지 모릅니다. 그래서 HTTP/1.1 편지 안에 **`Host: 쇼핑몰.com`**을 꼭 적게 만들어, 서버가 보고 알맞은 사이트를 보여주게 한 것입니다.

### Q4. HTTP/1.1도 데이터를 쪼개서 보내는데 HTTP/2와 뭐가 다른가요?
* **HTTP/1.1**: 네트워크 선이 한 번에 큰 데이터를 못 보내서 밑단(TCP)에서 조각내어 보내긴 하지만, **첫 번째 파일(HTML)이 다 도착해야만 두 번째 파일(CSS)을 보낼 수 있습니다.** 첫 번째가 느리면 뒤가 다 막힙니다(HOL Blocking).
* **HTTP/2**: 아예 편지들을 조각조각 내고 각 조각에 번호표(`Stream ID`)를 붙여서, **HTML 조각 1개 → CSS 조각 1개 → 이미지 조각 1개** 순서로 섞어서 동시에 보내고 받는 쪽에서 번호표대로 다시 조립합니다.

### Q5. 정적 파일을 보낼 때 왜 `stat()`을 확인하고 `16KB`씩 나눠 보낼까요?
* `stat()`을 호출하면 파일을 다 읽지 않고도 *"이게 진짜 파일인지, 폴더인지, 읽기 권한은 있는지, 크기가 몇 바이트인지"* OS(파일의 `inode` 정보)에서 바로 알 수 있습니다.
* 크기가 100MB인 파일이라고 해서 `malloc(100MB)`로 한 번에 메모리에 올리면 동시 접속 10명만 와도 1GB 메모리가 날아갑니다. 그래서 `16KB`씩 조금씩 읽어서 보내야 메모리가 안정적입니다.

## 3. 소켓 코드 짤 때 무조건 기억할 3가지 공식

1. **서버가 문 열 때 순서**:
   `getaddrinfo`(주소 준비) → `socket`(전화기 만들기) → `setsockopt(SO_REUSEADDR)`(재시작 허용) → `fcntl(O_NONBLOCK)`(논블로킹) → `bind`(번호 등록) → `listen`(손님 대기)
2. **프록시가 다른 서버에 전화 걸 때 순서**:
   `getaddrinfo` → `socket` → `fcntl(O_NONBLOCK)` → `connect`
   *(주의: 논블로킹이라 바로 연결 안 되고 `EINPROGRESS`("연결 중이야")가 뜹니다. 알림판에서 쓰기 가능 신호가 오면 `getsockopt(SO_ERROR)`로 연결 성공 여부를 확인하세요.)*
3. **`read()` / `write()` 반환값 4가지 구별하기**:
   * **양수(`> 0`)**: 그 숫자만큼 글자를 읽거나 썼다는 뜻 (성공).
   * **`0` (`read`일 때)**: 상대방이 정상적으로 연결을 끊었다(`EOF`)는 뜻 → 나도 닫기.
   * **`-1`인데 `errno == EAGAIN`**: 에러가 아니라 *"지금 보낼/받을 데이터가 잠깐 없으니 다음에 다시 시도해"*라는 뜻 → 그대로 두고 다음 알림 기다리기.
   * **`-1`인데 `errno == EPIPE` 또는 `ECONNRESET`**: 상대방이 갑자기 연결을 끊고 나갔다는 뜻 → 당황하지 말고 조용히 내 쪽 연결 닫고 메모리 정리하기.
