# verify 폴더 운영 규칙

검증 문서는 목적별로 나눕니다. 한 문서에 실행 기록, 설계 비판, 권고를 함께 넣지 않습니다.

| 파일 | 무엇을 담나 | 성격 | 갱신 시점 |
|---|---|---|---|
| `README.md` | 이 폴더의 분류와 규칙 | 안내 | 규칙이 바뀔 때 |
| `TEST_MATRIX.md` | 요구사항 → 검증 명령 → 현재 상태 | 현재 상태 | 요구사항이나 테스트가 바뀔 때 |
| `VERIFICATION_LOG.md` | 실제 실행 명령, 출력 요약, 날짜, 통과/실패 | 실행 기록(append) | 테스트를 실행할 때마다 |
| `ARCHITECTURE_REVIEW.md` | 현재 구조, 리스크, 완료 항목, 다음 우선순위 | 현재 상태 | 구조/배포가 바뀔 때 |
| `DESIGN_REVIEW.md` | 초기 설계 시점의 검토 기록 | 과거 기록(보존) | 수정하지 않고 링크만 유지 |

## 원칙

- "완료"라고 적으려면 `VERIFICATION_LOG.md`에 실제 실행 기록이 있어야 합니다.
- 매트릭스는 요약이고, 증거는 로그에 있습니다. 같은 내용을 복사하지 않습니다.
- 실패, 미실행, 범위 밖도 그대로 적습니다. 지우지 않습니다.
- 과거 기록은 지우지 않고 `당시 …`, `이후 … 완료`로 표시합니다.
- 성능 수치는 요청 수, 동시성, 환경을 함께 적습니다.
- 제안은 "다음 우선순위"에 두고 완료 목록으로 옮기지 않습니다.

## 새 검증을 추가할 때

1. `TEST_MATRIX.md`에 요구사항과 명령을 추가하고 상태를 `NOT RUN`으로 둡니다.
2. 실행합니다.
3. `VERIFICATION_LOG.md`에 날짜·명령·조건·실제 결과를 append합니다.
4. 매트릭스 상태를 `PASS`, `FAIL`, `OUT OF SCOPE`, `SUPERSEDED` 중 하나로 바꿉니다.
5. 실패했다면 원인과 수정, 재검증 결과를 이어서 기록합니다.

필요해지면 `PERFORMANCE.md`(부하 결과만)와 `INCIDENTS.md`(실제로 만난 문제와 수정)를 분리합니다.
지금은 위 5개로 충분합니다.
