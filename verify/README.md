# verify 폴더 운영 규칙

검증 결과와 설계 리뷰를 구분해 둡니다. 실행하지 않은 것은 적지 않습니다.

| 파일 | 무엇을 담나 | 갱신 시점 |
|---|---|---|
| `VERIFICATION_LOG.md` | 실제로 실행한 명령, 출력 요약, 날짜, 통과/실패. 실패도 그대로 남김 | 코드/빌드/테스트가 바뀔 때마다 |
| `ARCHITECTURE_REVIEW.md` | 현재 구조, 리스크, 완료/미완 상태, 다음 우선순위 | 구조나 배포 형태가 바뀔 때 |
| `DESIGN_REVIEW.md` | 설계 문서 대비 구현 차이, 발견한 문제와 제안/거절 근거 | 설계 결정이 바뀔 때 |

원칙:

- "완료"라고 적으려면 그 항목을 실제로 실행한 로그가 `VERIFICATION_LOG.md`에 있어야 합니다.
- 추측이나-plan은 `ARCHITECTURE_REVIEW.md`의 우선순위 항목으로만 적고, 완료로 옮기지 않습니다.
- 성능 수치는 부하 조건(요청 수, 동시성, 환경)을 함께 적습니다.
- possible한 실험(`io_uring`, `SO_REUSEPORT`)은 완료 목록이 아니라 "다음 우선순위"에 둡니다.

필요해지면 `PERFORMANCE.md`(부하 결과만)와 `INCIDENTS.md`(실제로 만난 버그와 수정)를
분리하겠습니다. 지금은 위 3개로 충분합니다.
